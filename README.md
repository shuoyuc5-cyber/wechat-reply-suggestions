# 微信回复建议 1.7.9

Apple Silicon 原生 Mac 容器应用，系统风格侧边栏、轻量表单、深浅色自适应。界面基于内嵌 WebKit，标题栏、授权和密钥输入使用原生 Cocoa。

## 读取与自动更新

1. 在微信打开一个单人文字聊天，点击「开始读取」；也可直接打开「自动更新当前会话」开关。
2. 首次使用推荐选区：橙色为标题区，绿色为消息区。确认没包含左侧会话列表及输入框后，点「使用选区」。不合适时点「手动调整」。推荐位置是按窗口布局估算，必须由你核对。
3. 核对识别出的联系人名称，选择独立档案并同意读取和保存。识别不清会停止，不猜测联系人身份。
4. 自动更新每 4 秒一次。关闭开关仅暂停，保留当前会话及选区；再次打开会重新核对标题，无需重复框选。切换会话、导航键、点击左侧会话列表、窗口变化、锁屏或识别失败会结束授权并清空上下文。
5. 普通打字及在聊天内容/输入区点击，不再直接中断自动更新。身份检查仍在每次识别前后执行。

快捷键 Control + Option + R 显示或隐藏助手；隐藏结束本次会话授权。重开后需要再次确认。关闭主窗口退出应用；框选浮层期间不会因为主窗口隐藏而退出。

## 生成模型

默认是本地 Ollama qwen3:8b，另可选择 DeepSeek API 或 Gemini API。

- DeepSeek 默认 deepseek-flash，也可输入 deepseek-v4-pro。
- Gemini 默认 gemini-3.8-flash，模型字段可填写你账户支持的其他 gemini- 开头模型名。
- 「设置 Gemini Key」与「设置 DeepSeek Key」分别使用原生安全输入框，Key 分别保存到 macOS 钥匙串；不写入档案、网页或日志。原有 DeepSeek Key 存储位置保持兼容。
- 每次云端生成前展示本次将发送的当前上下文、当前档案历史和意图，你确认后才发送。Gemini 固定发往 generativelanguage.googleapis.com，DeepSeek 固定发往 api.deepseek.com；不发图片、不自动重试扣费。API 用量按服务商账户规则计费。
- 云端调用尚未用你的 Key 实测。需要由你在应用中填写并确认一次请求。不要把 Key 发到聊天里。

官方接口：https://ai.google.dev/gemini-api/docs/openai 和 https://api-docs.deepseek.com/ 。

## 档案与隐私

档案位于 ~/Library/Application Support/微信回复建议/Contacts/<独立编号>/profile.json。每人最多保留 10 次不同的可见上下文片段，生成时最多读同一档案的两个历史片段。文件权限 600，目录 700；内容为本机明文。退出会清除会话授权，档案继续保留。同名默认新建，只有你明确选择时才复用。

手动 OCR 和自动会话模式使用系统 ScreenCaptureKit，只处理用户确认的区域。可选「本地 AI 选区」在每次明确确认后截取整个所选微信窗口（可能包含会话列表和消息），只交给本机 Ollama 分析位置，不保存截图、不发送给云端；其建议选区仍须用户检查确认。文字用 Vision 在本机识别。OCR 会有错字，气泡角色基于位置与绿色背景推断，不是微信原始数据；群聊、图片和自定义气泡可能不支持。标题不是唯一账号 ID；同名联系人仍须人工确认。

## 构建

运行 ./build.sh。使用系统 Swift、Cocoa、WebKit、ApplicationServices、Carbon、ScreenCaptureKit、Vision、Security；不依赖 Python 或浏览器端口。不会自动发送微信消息。

识别思路参考 terryyang20233/wechat-auto-reply（MIT），许可见 THIRD_PARTY_LICENSE.txt。

## 屏幕访问排错

「检查屏幕访问」只通过 ScreenCaptureKit 获取窗口元数据，不截图或识别聊天正文。以系统接口实际结果为准，移除旧 CGPreflight 前置拦截及重复 CGRequest 请求。系统拒绝访问后停止自动重试，须明确点击检查才再尝试。错误显示当前应用路径及系统错误类型；窗口/识别错误不会当成权限问题。只启动 /Applications/微信回复建议.app，避免同名开发副本。

本机构建使用临时签名；更新程序会改变签名，旧的系统授权可能失效。最终安装后若系统仍拒绝且开关已开，完全退出后在设置中移除旧条目，再添加 /Applications/微信回复建议.app 并重开。授权操作由用户完成。不会修改系统权限数据库。

## 截图与生成修复（1.5.2）

macOS 26 及以上采用专用的 SCScreenshotConfiguration/captureScreenshot 接口，旧系统保留截图兼容调用。选区从窗口坐标映射到 filter.contentRect，输出尺寸使用系统 pointPixelScale。严格只捕获所选区域，不退回全屏或整个窗口；不采集声音，不保存截图。聊天上下文为空时禁用生成按钮，读入后明确提示点击生成，云端仍每次单独确认。

## 识别核对修复（1.5.3）

首次读取正文，或任意文字/说话人识别不确定时，暂停自动更新并显示可编辑的本机识别预览，不因一行识别不清就撤销会话。低置信文字与不明说话人分别明确标记；必须修改或删除所有待核对标记后才能确认。确认后再次校验聊天标题和窗口，才保存到当前档案并允许生成。取消不保存该次内容，保留选区以便重试。核对后自动更新保持暂停，用户可重新开启。身份变化仍结束授权并清空上下文。

## 1.6：图标、Humanizer 与中英文

新图标为原创蓝白对话气泡，参考 macOS 的圆角、层次与简洁构图；不是苹果或微信官方图标。

侧边栏「界面语言 / Language」可选简体中文或 English，立即生效并记住选择。主界面、菜单、选区提示、OCR 核对窗口、API Key 弹窗及云端发送确认支持英文。界面切换保留聊天内容、意图与已有回复。

「更自然 · Humanizer」默认开启，可关闭。它在现有生成请求中加入口语化、自检和保留事实的规则，本地和两种云端模型均适用，不额外发送润色请求，不提供 AI 鉴定分数。具体研究与取舍见 HUMANIZER_INTEGRATION.md。

「回复语言」单独选择跟随聊天、中文或 English，不跟随界面语言。所有生成都需要用户点击；云端仍逐次确认；本次变更不自动开启读取或发送消息。

验证：Swift 编译、提示词与原生语言分支检查、DOM 中英文切换及内容保留测试通过。受当前环境限制，未完成新版 macOS 窗口实测及真实聊天/云端模型实测。

## 一次性 OCR 并生成（1.6.1）

默认入口改为「框选消息 · OCR」。只框选对方发来的文字气泡，不含自己的回复；点击识别，核对本机 OCR 文字并确认其为收到的消息后，直接生成三条建议。云端仍单独展示发送内容和费用并征求同意。该流程不识别联系人、不访问历史档案、不保存截图或聊天档案、不持续读取或发送消息。

单次模式不依赖标题 OCR、会话标识或气泡说话人推断。角色来自用户核对时的明确确认。低置信文字也先展示以便修改，空白、无文字或超限选区明确报错；取消不会生成。当前意图、语气和模型在开始框选时固定，确认后只触发一次生成；过期或重复请求在原生端拦截。

原来的双区域标题校验、独立档案和自动刷新保留在「会话自动读取」入口；自动更新开关仍属于这个模式。中英文界面、独立回复语言和 Humanizer 保留。

测试覆盖：单区域选择、无文字/超限/低置信文字、生成消息桥接恰好一次、意图和语气保留、旧识别保护逻辑。当前环境无可用的桌面操作工具，真实微信窗口识别及完整界面流程仍需在用户端验证。

## 浮窗与本地视觉选区（1.7）

完整主界面保留为普通 NSWindow；小浮窗是单独的 NSPanel，仅显示快捷按钮和回复结果，可置顶、拖动和缩放。被动显示时不主动抢焦点；点击浮窗才进入交互。浮窗顶部有手动框选、AI 选区、展开和隐藏。展开后可在侧边栏「切换小浮窗」返回；模式、位置和大小会记住。隐藏或关闭浮窗会停止读取、取消进行中的选区分析并结束会话授权，Control + Option + R 可重新显示。

「本地 AI 选区」优先复用已安装的 qwen2.5vl:7b，其次 llava:7b，运行前检查 vision 能力并拒绝远程模型。仅调用固定本机地址 http://127.0.0.1:11434，无代理、Cookie 或重定向；与回复模型选择独立。按下该按钮后会单独说明整个所选微信窗口的截图范围，用户可同意本机分析或改为手动框选。图片仅在内存，缩放后交给本机模型定位，不索取或保存联系人、消息转录。模型返回输入图片上的像素矩形，程序按实际图像尺寸映射到窗口坐标，并增加文字边缘留白，校验坐标、尺寸和窗口变化；不合格、无模型或超时都退回手动。分析结束后释放视觉模型，避免长时间占用内存。

绿色框只是建议，用户仍须检查是否只包含对方发来的文字，必要时点手动调整，再识别并核对内容。AI 没有被授予自动发送消息、扫描其他应用、持续截图或写入历史档案的权限。会话自动读取模式不再按固定窗口百分比猜选区，改为手动确认标题和消息区。

测试：浮窗/展开界面切换保留文字和语气，紧凑入口与隐藏消息、AI JSON/坐标安全校验、多屏边界和旧 OCR 桥接均有检查。真实桌面浮窗行为及真实微信选区准确度尚未实测，不能保证自动框总是正确。

接口参考：https://ollama.com/library/qwen2.5vl ，https://docs.ollama.com/capabilities/vision ，https://ollama.com/blog/structured-outputs 。

本机视觉接口已使用虚构聊天截图测试：Qwen2.5-VL 返回位置，经像素坐标换算与边缘留白后覆盖了最后一条收到的文字消息。该样例不代表真实微信布局下的准确率。

## 主窗口、下拉菜单与窗口授权修复（1.7.1）

1. 语气、模型、语言等下拉菜单统一放在普通完整主窗口。侧边栏可显示/隐藏独立浮窗，浮窗的「完整界面」打开原主窗口。浮窗不再承载下拉菜单，也不再缩放或隐藏主窗口内容。
2. OCR 默认使用 macOS SCContentSharingPicker 选择单个微信窗口。程序验证窗口属于 com.tencent.xinWeChat，并直接使用系统返回的 SCContentFilter 截图，不再枚举全部可截图窗口或依赖旧的全屏录制权限预检查。此路径需要 macOS 15.2+（当前 Mac 27.x 支持）。系统选择器由用户确认，不代替用户授权。
3. 系统授权后再框选区域，或单独同意本地 AI 分析整个所选微信窗口；核对文字后原生端直接生成，不依赖某个 WebView 是否可见。浮窗使用主窗口已选的语气、模型和意图，不重复发起生成。两边只展示符合当前上下文的回复。
4. 主窗口和浮窗均强引用、关闭时隐藏而非释放。关闭最后一个窗口不自动终止应用；需要退出时用应用菜单或在助手中按 Command+Q。隐藏/关闭会停止读取并撤销本次所选窗口访问。截图选区的面板释放延后到当前鼠标事件结束。
5. 未找到助手自身的崩溃报告，因此不能断言已复现实机闪退根因。编译、主/浮窗 UI 状态、下拉菜单归属、OCR 不重复生成、窗口来源白名单和旧识别逻辑测试通过。真实桌面下拉交互及系统授权回调仍需安装后实测。

Apple 官方说明系统选择器提供的 filter 可用于截图接口：https://developer.apple.com/videos/play/wwdc2023/10136/ 。没有更改权限数据库、降低签名验证或绕开系统授权。

## 浮窗、OCR 衔接与粘贴修复（1.7.2）

- 每次新进程启动强制关闭浮窗，即使上次启用过。主界面顶部提供「启用悬浮窗」开关，原侧栏按钮保留；均只控制独立浮窗，不改变完整主界面。
- 标准 macOS 编辑菜单支持撤销、重做、剪切、复制、粘贴、全选；上下文框始终可编辑，另提供原生「粘贴聊天」按钮。仅在明确点击粘贴时读取剪贴板。手动编辑会解除自动读取、窗口授权和联系人关联；用事件版本号拒绝迟到的自动读取覆盖手动文字。不会把手动文字写入旧联系人档案。
- 单次手动框选松开鼠标后自动开始 OCR，不再等额外的「识别选区」点击。AI 建议选区仍须手动确认。OCR 文字在核对弹窗出现时先展示到上下文，确认之前禁用生成；取消不会自动生成，可以编辑后手动生成。
- 所选微信截图调用最多等待 15 秒；失败显示原因，不再无限等待。重复/迟到的系统回调只完成一次。窗口几何比较允许 1 点的系统浮点差异，较大移动、尺寸或来源变化仍会拒绝。
- 确认 OCR 后由原生端生成；已有生成任务时保留一个最新待处理请求，旧任务结束后继续。切换上下文或隐藏时清除待处理请求，不重复计费发起后台重试；云端生成仍单独确认。

验证覆盖：开关/启动策略、始终可编辑上下文、原生粘贴动作、编辑解除关联与迟到消息、OCR 预览/确认/三条建议渲染、截图超时和一次性回调、队列过期丢弃及清理。当前没有桌面控制工具，真实微信截图到 OCR 的整条链路和实际键盘 Cmd+V 仍需用户端验证；未声称已实机复现全部故障。
